# workation-mobile 개발 가이드

이 문서는 처음 레포를 받은 팀원이 환경을 맞추고, 화면을 추가하고, PR 을 올리기까지 필요한 규칙을 정리합니다.

## 1. 환경 설정

### 필수 도구

| 도구 | 버전 | 비고 |
| --- | --- | --- |
| Flutter SDK | 3.47 stable | [docs.flutter.dev/get-started](https://docs.flutter.dev/get-started/install). 팀 전체가 같은 마이너 버전을 쓰는 것을 권장 |
| Android Studio | 최신 | Android SDK 36, 에뮬레이터 |
| Xcode | 16 이상 | iOS 빌드는 macOS 에서만 가능. `sudo xcodebuild -license` 와 CocoaPods 필요 |
| 에디터 | VS Code 또는 Android Studio | Flutter / Dart 확장 설치 |

설치 후 `flutter doctor` 에서 Flutter, Android toolchain, (macOS 라면) Xcode 가 `[✓]` 인지 확인합니다. Chrome 항목은 이 프로젝트에서 쓰지 않으므로 무시해도 됩니다.

### VS Code 확장

- `Dart-Code.flutter`, `Dart-Code.dart-code` — 필수
- 저장 시 포맷: `.vscode/settings.json` 에 `"editor.formatOnSave": true` (개인 설정이라 커밋하지 않음)

### 처음 한 번

```bash
git clone https://github.com/TEAM-SKPJC/workation-mobile.git
cd workation-mobile
flutter pub get
flutter devices                 # 연결된 디바이스/에뮬레이터 확인
flutter run                     # mock 데이터로 실행 (USE_MOCK 기본값 true)
```

하단에 홈 · 지도 · 즐겨찾기 · MY 탭이 보이면 정상입니다. 백엔드에 붙일 때는 `--dart-define=USE_MOCK=false --dart-define=API_BASE_URL=http://localhost:8000` 을 줍니다.

### 실행 설정 저장 (선택)

매번 `--dart-define` 을 치지 않도록 `.vscode/launch.json` 을 둘 수 있습니다 (개인 설정).

```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "workation (mock)",
      "request": "launch",
      "type": "dart"
    },
    {
      "name": "workation (local API)",
      "request": "launch",
      "type": "dart",
      "toolArgs": [
        "--dart-define=USE_MOCK=false",
        "--dart-define=API_BASE_URL=http://localhost:8000"
      ]
    }
  ]
}
```

## 2. 일상 작업 흐름

브랜치·커밋·PR·라벨 규칙의 기준 문서는 [협업 규칙](https://github.com/TEAM-SKPJC/workation-docs/blob/main/협업/협업-규칙.md) 입니다. 아래는 그 요약입니다.

1. 이슈 템플릿(✨ Feature / 🐛 Bug / ♻️ Refactor / ❗ Etc)으로 이슈를 먼저 만들고 이슈 번호를 받습니다
2. `main` 에서 브랜치 생성: `feat/M-02-region-detail` 처럼 `타입/화면ID-설명`
3. 개발하며 `flutter run` 상태에서 `r`(핫 리로드)로 확인
4. 커밋 전 `dart format . && flutter analyze && flutter test` 가 모두 통과하는지 확인
5. PR 생성. PR 템플릿의 `🔗 이슈` 에 `close #번호` 를 적으면 merge 시 이슈가 자동으로 닫힙니다. GitHub Actions CI(`dart format` 검사, `flutter analyze`, `flutter test`)가 자동 실행되며 결과가 PR 에 표시됩니다
6. CI 가 초록색이면 `main` 에 squash merge (merge commit·rebase 는 레포 설정에서 비활성화)

### 커밋 메시지

Conventional Commits 를 따릅니다.

```
feat: M-02 지역 상세 화면 레이아웃
fix: 홈 카드 이미지 비율 깨짐 수정
chore: 의존성 업데이트
docs: 개발 가이드 보강
refactor: ScoreDisplay 위젯 분리
test: 홈 화면 위젯 테스트 추가
```

## 3. 화면 추가하기

화면 ID(M-01~M-07)와 기능 단위로 `lib/features/<기능>/` 폴더를 만듭니다. 화면 목록과 구현 단계는 [구현 플랜](plans/2026-11-08-모바일-구현-plan.md)의 "화면별 구현 메모" 표가 기준입니다.

1. `lib/features/region/region_screen.dart` 생성 (snake_case 폴더·파일, `Screen` 접미사)

```dart
import 'package:flutter/material.dart';

/// M-03 지역 상세
class RegionScreen extends StatelessWidget {
  const RegionScreen({super.key, required this.regionId});

  final String regionId;

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('지역 상세')),
      body: Center(child: Text(regionId)),
    );
  }
}
```

2. 화면 전용 위젯·provider 는 같은 폴더에 둡니다.
   예: `features/region/widgets/monthly_crowd_chart.dart`, `features/region/region_providers.dart`
3. 두 화면 이상에서 재사용되면 위젯은 `lib/shared/widgets/`, 모델·리포지토리는 `lib/data/` 로 올립니다.
4. 라우트를 `lib/app/router.dart` 에 등록합니다 (go_router).
   - 하단 탭 화면(홈 · 지도 · 즐겨찾기 · MY)은 `StatefulShellBranch` 하나씩입니다. 탭마다 스택이 따로 유지됩니다.
   - 상세 화면은 들어오는 탭의 branch 아래 하위 라우트로 둡니다. 예: 홈 branch 의 `GoRoute(path: '/', routes: [GoRoute(path: 'regions/:id', ...)])`
   - 이동은 `context.go('/regions/51820')`(스택 교체) 또는 `context.push(...)`(쌓기). 경로 문자열은 `AppRoutes` 상수로 모읍니다.
5. 아직 구현하지 않은 탭 화면은 `ScreenPlaceholder` 로 자리만 둡니다.

## 4. 코드 규칙

### Dart

- `flutter_lints` 권장 규칙이 전부 켜져 있고 `flutter analyze` 에서 경고 0 을 유지합니다.
- 모든 위젯 생성자는 `const` 가능하면 `const` 로, `super.key` 를 받습니다.
- 파일·폴더는 snake_case, 클래스는 PascalCase, 변수·함수는 camelCase.
- 상수 모음은 `abstract final class` 로 묶습니다 (`AppColors`, `ApiConfig` 참고).
- 포맷은 `dart format` 기본값(80자)을 따릅니다.

### 위젯

- 가능한 한 `StatelessWidget`. 데이터가 필요하면 `ConsumerWidget` 으로 provider 를 읽습니다. 애니메이션 컨트롤러 · 텍스트 입력처럼 위젯 안에서 끝나는 상태만 `StatefulWidget` 에 둡니다.
- `build` 메서드가 길어지면 private 메서드가 아니라 별도 위젯 클래스로 분리합니다 (리빌드 범위 최소화).
- 색상은 `Theme.of(context).colorScheme`(primary=brand, onSurface=잉크, outlineVariant=헤어라인 등) 또는 `Theme.of(context).extension<AppSemanticColors>()!`(grade·signal·chart·heat) 만 사용합니다. 위젯 안에 `Color(0xFF...)` 직접 작성을 금지합니다.
- 텍스트는 `AppTextStyles.headingXl` 처럼 Figma 텍스트 스타일 이름 그대로 씁니다. 색만 바꿀 때는 `copyWith(color: …)`.
- 간격은 `AppSpacing.s1~s16`(4px 단위), 라운드는 `AppRadius.lgAll/xlAll/xxlAll/fullAll`, 그림자는 `AppShadows.cardFloat` 하나만 씁니다.
- Black Han Sans(`AppTextStyles.displayLogo/displayHero`)는 로고·히어로·공유 카드 제목에만 씁니다.
- 아이콘은 Figma 와 같은 lucide 를 씁니다(`lucide_icons_flutter` 의 `LucideIcons.xxx`). lucide 에 없는 것(월계수 · 채운 북마크)만 `assets/icons/*.svg` 를 `flutter_svg` 로 그립니다.
- Figma 공통 컴포넌트는 `lib/shared/widgets/` 에 같은 이름으로 있습니다(`Tag` · `GradeBadge` · `AppChip` · `ListingCardMobile` · `DongRow` · `PhotoHeader` · `ScoreDisplay` · `SegmentedTabs` · `MobileStickyBar` · `TypeBar` · `FactPill` · `SearchPillMobile` · `CategoryTab` · `IconButtonCircle`). 새로 만들기 전에 먼저 찾아봅니다.

### 상태관리 (Riverpod)

- `flutter_riverpod` 을 씁니다. 앱은 `main.dart` 의 `ProviderScope` 아래에서 돕니다.
- **서버 데이터**(지역 목록 · 상세 · 곡선 등)는 `FutureProvider` 또는 `AsyncNotifierProvider` 로 둡니다. 화면은 `ref.watch(...).when(data:, loading:, error:)` 로 세 상태를 모두 그립니다. 인자가 있으면 `.family` 를 씁니다.
- **화면 사이에 공유하는 값**(선택한 월 · 프리셋 · 로그인 상태)은 `NotifierProvider` 로 둡니다.
- provider 는 기능 폴더의 `<기능>_providers.dart` 에, 여러 기능이 쓰면 `lib/data/` 에 둡니다. 이름은 `xxxProvider` 로 끝냅니다.
- 위젯에서 리포지토리 · Dio 를 직접 만들지 않습니다. 항상 provider 로 받습니다. 그래야 테스트와 mock 에서 `ProviderScope(overrides: [...])` 로 바꿔 끼울 수 있습니다.

### 네트워크

- 백엔드 호출은 `ApiClient`(`lib/core/network/api_client.dart`, `apiClientProvider`)로만 합니다. Dio 를 직접 쓰지 않습니다.
- 경로는 웹(workation-web `src/lib/api.ts`)과 같이 호출부에서 `/api/...` 로 시작합니다. 예: `client.get('/api/regions/popular', query: {'month': 10})`. 호스트는 `ApiConfig.baseUrl` 입니다.
- 실패는 모두 `ApiException`(`NetworkException` · `UnauthorizedException` · `NotFoundException` · `ServerException` · `UnknownApiException`)으로 던져집니다. 화면은 이 타입으로 에러 문구와 "다시 시도" · 로그인 모달을 고릅니다.
- 모든 요청에 `X-Requested-With: workation-mobile` 헤더가 붙습니다(웹과 같은 CSRF 확인용).

### mock 데이터

- 백엔드 엔드포인트가 열리기 전까지 리포지토리는 mock 으로 동작합니다. 스위치는 `--dart-define=USE_MOCK=true|false`(`ApiConfig.useMock`, 기본 true).
- 리포지토리는 추상 클래스 + `Api…Repository` + `Mock…Repository` 로 만들고, provider 가 `ApiConfig.useMock` 을 보고 하나를 고릅니다. mock 응답은 `assets/mock/*.json` 에 두고 `MockAssets` 로 읽습니다. 파일별 출처는 `assets/mock/README.md` 에 적습니다.
- 위젯 테스트에서는 실제 에셋 읽기가 끝나지 않으므로 mock 리포지토리 대신 가짜 리포지토리를 override 합니다(`test/helpers.dart` 의 `pumpApp` · `FakeRegionRepository`).
- 시안 사진은 `assets/mock-photos/` 에 각자 내려받아 두고 커밋하지 않습니다. 없으면 `AppPhoto` 가 회색 상자로 그립니다.

### 코드 생성 (freezed · json_serializable)

- API 응답 모델은 `freezed` + `json_serializable` 로 만듭니다(M1 부터).
- 모델을 추가 · 수정하면 생성 파일을 다시 만듭니다. 생성 파일(`*.g.dart`, `*.freezed.dart`)도 커밋합니다(CI 에서 build_runner 를 돌리지 않기 때문).

```bash
dart run build_runner build --delete-conflicting-outputs
```

## 5. 테스트

```bash
flutter test                   # 전체
flutter test test/widget_test.dart
```

- 화면 하나당 "렌더링되고 핵심 텍스트가 보인다" 수준의 위젯 테스트를 최소 1개 둡니다.
- 앱 전체를 띄우는 테스트는 `ProviderScope(child: WorkationApp())` 로 감쌉니다. 데이터는 `ProviderScope(overrides: [...])` 로 가짜 리포지토리를 넣습니다.
- 네트워크 테스트는 실제 서버를 부르지 않고 Dio 의 `httpClientAdapter` 를 가짜로 바꿉니다(`test/core/network/api_client_test.dart` 참고).
- 테스트 파일은 `test/` 아래에 `lib/` 구조를 그대로 미러링합니다. 예: `test/features/home/home_screen_test.dart`

## 6. 에셋 추가

### 이미지

`assets/images/` 에 넣으면 pubspec 에 이미 폴더가 등록되어 있어 바로 쓸 수 있습니다.

```dart
Image.asset('assets/images/jeju.jpg')
```

### 폰트

Noto Sans KR · Black Han Sans · Gaegu 가 `assets/fonts/` 에 번들되어 `pubspec.yaml` 에 등록돼 있습니다. 서체를 추가할 때는 같은 방식으로 파일을 넣고 `flutter.fonts` 에 등록한 뒤 `AppTextStyles` 에 상수를 추가합니다.

## 7. 빌드

```bash
flutter build apk --release --dart-define=API_BASE_URL=https://api.example.com
flutter build appbundle --release --dart-define=API_BASE_URL=https://api.example.com   # Play Store
flutter build ipa --release --dart-define=API_BASE_URL=https://api.example.com         # App Store
```

- Android 서명 키(`key.properties`, `*.jks`)와 Firebase 설정 파일은 `.gitignore` 에 있으므로 절대 커밋하지 않습니다. 팀 공유 저장소(1Password 등)로 전달합니다.
- iOS 는 Apple Developer 계정과 프로비저닝 프로파일이 필요합니다.

## 8. 자주 겪는 문제

| 증상 | 원인 / 해결 |
| --- | --- |
| 에뮬레이터에서 `localhost:8000` 연결 실패 | Android 에뮬레이터는 호스트가 `10.0.2.2` 입니다. iOS 시뮬레이터는 `localhost` 그대로 |
| `flutter doctor` 에서 Xcode `[!]` | `sudo xcode-select -s /Applications/Xcode.app`, `sudo xcodebuild -runFirstLaunch`, CocoaPods 설치 |
| 패키지 추가 후 빌드 에러 | `flutter clean && flutter pub get`. iOS 는 `cd ios && pod install` 추가 |
| `--dart-define` 변경이 반영 안 됨 | 컴파일 타임 상수라 핫 리로드로는 안 바뀝니다. 앱을 다시 `flutter run` |
| analyze 경고 `prefer_const_constructors` | 생성자에 `const` 추가 |
